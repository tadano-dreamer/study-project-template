# 演習台帳

正誤だけでなく**確信度**も取り、**正誤 × 確信の4象限**で診断する。
設計の根拠は `../../docs/01_設計思想.md` 判断3・判断5・判断13。

```
ledger/
├── questions.tsv      問題マスタ（Claude が作る。正解を持つので学習中は開かない）
├── rounds/
│   ├── round0/*.md    プレテスト
│   ├── round1/*.md    1周目の解答ノート ← ★人が触るのは、ここと手書きページと一問一答のページ
│   └── round2/*.md    2周目
├── 手書き/            途中式の手書きページ（Excalidraw・小問ごとに1枚）と、作る・読む道具
├── recall-log.tsv     想起テストの正答率（日替わりページの読み取りと recall-drill が追記）
├── tally.py           集計
├── daily.py           一問一答の日替わりページを作る・読む（`../一問一答/毎日/`）
└── test_tally.py / test_daily.py   道具を触ったら流す
```

---

## 4象限

|  | 確信あり | 確信なし 🤔 |
|---|---|---|
| **正解** | ✅ 定着 | ⚠️ **たまたま正解** |
| **不正解** | 🔴 **誤解** | ⬜ 未学習 |

- 🔴 **誤解** — 自信を持って間違えた。**知識そのものが間違っている。** 概念の再学習が要る
- ⚠️ **たまたま正解** — 当たったが根拠がない。**本番で落とす最有力候補。** 根拠の言語化が要る

**この2つは処方が違う。** 不正解だけを追うと ⚠️ が丸ごと見えなくなる。

## 解答ノートの書き方

**タップするのは「選んだ肢」と「🤔自信なし」だけ。正誤は自動判定される。**

```markdown
## 1-01 用語と計算の基本

### (1)
📖 問題集 p.12 ／ ✏️ [[1-01-01.excalidraw|途中式]]

- [ ] A
- [ ] B
- [x] C          ← 選んだ肢
- [ ] D
- [ ] 🤔 自信なし

### (2)
- [x] A
- [ ] B
- [ ] C
- [ ] D
- [x] 🤔 自信なし   ← 自信がなければタップ
```

### 選択肢のない問題（記述・計算）だけ手で付ける

```markdown
### (3)
- [ ] 🤔 自信なし
- [x] ⭕ 正解
```

`⭕` か `❌` の**どちらかを必ず**タップする。
無印を正解扱いにすると**未着手と区別がつかなくなる**ため。

### 見出しの規則

- `## <大問id> <タイトル>` — id は `questions.tsv` の `id` の大問部分と一致させる
- `### (n)` — 小問番号。台帳上の id は `<大問id>-<n>` になる。`(n)` の後ろに、教材と同じ呼び方（`問2〔1〕` など）を書いてよい

### ノートに書くこと・書かないこと

- **📖 教材の実際のページを、各問に書く**（`📖 問題集 p.12`）。目安しか書けないときは「ごろ」と書き、User が解く前に確かめてもらう
  （統計検定2級の2周目は、PDF から割り出した目安が2ページずれ、問題を探す手間になった）
- **問題文は写さない**（著作権）。ノートにあるのは番号・チェック欄・ページ・手書きページへのリンクだけ
- **分野・型（誤選択か）・前回の答えは書かない。** 目印を付けると、設問を読み違える癖が測れなくなる。前回の肢が見えると答えの手がかりになる
- 解き終えたら User はチャットで一言伝えるだけ。**スクリーンショットは要らない**（正解は `questions.tsv` にある）

## 手書きページ（`手書き/`・Excalidraw）

途中式を Claude の分析対象にするための、**小問ごとに1枚**の手書きページ。
統計検定2級で学習者が「これ1番重要ですね」と言った部品（根拠は `docs/01_設計思想.md` 判断13）。
**既定は「あり」。** 要らない種類の問題があるかは、立ち上げのときに聞く。

```
手書き/
├── tools/gen_pages.py       ページを作る（解答ノートの小問ごと。手書きの線は残す）
├── tools/read_pages.py      書き込みのあるページだけ PNG にする（Claude が Read で読む）
├── tools/excalidraw_io.py   Drawing の読み込み（平文 json と、タブレットが保存する圧縮 compressed-json の両方）
├── tools/test_pages.py      gen_pages.py のテスト
├── round1/<ノート名>/<大問id>-<小問2桁>.excalidraw.md          例) round1/1章/1-01-02.excalidraw.md
└── round2/<ノート名>/<大問id>-<小問2桁>_2周目.excalidraw.md    1周目以外は名前に周回が付く
```

```bash
# 解答ノートを置いたら1回流す。--link は、各小問の見出しの下に「✏️ 途中式」の行を入れる
python ledger/手書き/tools/gen_pages.py --round 1 --link
```

要るもの: Obsidian の Excalidraw プラグイン（コミュニティプラグイン `obsidian-excalidraw-plugin`）。

- **答えと🤔は解答ノートでタップする。手書きページは途中式だけ。** ノートの各小問の `✏️ 途中式` で行き、ページ右上の `← 問題に戻る` でノートのその小問の見出しへ戻る
- ページは A4縦。ヘッダの下は全部が書く場所。**直しの区画は分けない**。黒と赤の色だけで分ける
- **色の決まり**: **黒 = 解いている間に書いたもの**（途中式・記述の○×・消去法のメモ）／ **赤 = 採点のあとの直し**。Claude は色で「本番の思考」と「あとからの修正」を分けて読む。赤は書かれなくてよい（統計検定2級では、直す役は Claude の解説へ移り、赤は275枚のうち1枚だった）
- 計算の無い問題は空のままでよい。空のページは読み取りで自動的に飛ばされる。2周目は、計算の無い問題も選んだ根拠を1行書いてもらう（自信なく当たった問題が、本当に根拠を持てたかを見るため）
- **1周目以外のページ名には周回が付く**（`_2周目`・`_プレテスト`）。同じ名前にすると、Obsidian の `[[1-01-02.excalidraw]]` がどちらを指すか決まらなくなる
- 解答ノートの見出しに `|` `#` `^` `[` `]` を入れない（`P(A|B)` など）。Obsidian がリンクの区切りとして読むので、「← 問題に戻る」がその見出しまでたどれず、ノートの先頭か大問の見出しに戻る
- `rounds/` の下には置かない（`tally.py` が `rounds/**/*.md` を解答ノートとして読むため）
- 手書きページは端末のあいだの同期に載せるため**コミットする**
- 🔴 **タブレットの Excalidraw は、開いていた古いページと pull した新しいページを要素ごとに混ぜて保存する**（統計検定2級で実測: 消したはずの区画と旧ヘッダが、新しいページに重なって復活した）
  - 対策（Claude 側）: ページの形を変えたら、古い要素の id を `gen_pages.py` の `RETIRED_IDS` に移す。「削除済み」の印（`isDeleted`・高い version）が自動で入る
  - 対策（User 側）: **Claude がページの形を変えたあとの pull は、Excalidraw のタブを閉じてから行う**（ふだんの pull では不要）

### Claude の読み方

```bash
# 書き込みのあるページだけ PNG にする（出力先は ASCII のパス。Chrome に全角パスを渡さないため）
python ledger/手書き/tools/read_pages.py ledger/手書き/round1/1章 <一時フォルダ>/hw
# → 「書き込みあり  1-01-02  線 42 本 -> …/003_1-01-02.png」の PNG を Read で開いて読む
```

**書き込みのあるページは全部読む。** 読んだら、その小問の正誤・🤔と突き合わせ、途中式のどこでずれたかを解説に書く。
**赤で公式が書いてあっても、理解した証拠ではない**（誤答して書き直したことが多い）。

## 問題マスタ `questions.tsv`

タブ区切り・UTF-8。

```
id	分野	型	正解	出典	メモ	元問題
1-01-1	A 基礎	選択	C	問題集 p.12	用語の定義	
1-01-3	A 基礎	誤選択	D	問題集 p.13	最も不適切なものを選べ	
2-02-2	C 発展	記述	-	問題集 p.45	導出を書く	
類題-基礎-01	A 基礎	選択	B	類題 1章	間違えた問題の類題	1-02-1
暗記-基礎-01	A 基礎	暗記	-	暗記カード 基礎	公式・定義のカード	
```

| 列 | 意味 |
|---|---|
| `id` | `<大問>-<小問>`。解答ノートの見出しと対応させる |
| `分野` | 集計の単位。初日ゲート2で作った分野リストを使う |
| `型` | `選択` / `誤選択` / `記述` / `暗記`（暗記カード） |
| `正解` | 選択肢がなければ `-` |
| `出典` | 後で解説を引くため。類題は `類題 {演習の名前}`、暗記カードは `暗記カード {分野名}` で始める |
| `メモ` | 一覧に出る短い説明 |
| `元問題` | **類題だけ書く。** どの問題の誤解を直すものか（複数ならカンマ区切り）。周回に着手記録が無いあいだは、元問題の象限を引き継いで `--next` に出る。空だと出題候補に入らず警告が出る。暗記カードは空（⬜未学習から始まる） |

### ★ `誤選択` を必ず分ける

「**最も不適切なものを選べ**」型を `誤選択` として区別する。
これが**設問反転の失点を数字にする唯一の手段**。

E資格では、この型で落とす癖に対策を決めた**後**に、また同じ型で落とした。
「注意しよう」では直らなかった。**測って数字にして、想起テストに混ぜる**のが処方。

## コマンド

```bash
python ledger/tally.py                 # 最新周回のサマリ
python ledger/tally.py --round 1       # 周回を指定
python ledger/tally.py --compare 1 2   # 逆行率・転換率
python ledger/tally.py --drill         # 直前の教材の材料（全周回＋一問一答の記録から、まだ直っていないものだけ）
python ledger/tally.py --drill --round 2   # その周回だけの優先復習リスト
python ledger/tally.py --next 15       # 次に出す問題（全周回＋類題＋暗記カード・間隔反復を加味）★recall-drill が使う
python ledger/tally.py --next 15 --kind 暗記   # 種類で絞る（類題 / 暗記 / 演習）
python ledger/tally.py --recall        # 想起テストの通算成績
python ledger/tally.py --detail        # 大問別の明細

python ledger/daily.py make            # 今日の日替わりページを作る（既にあれば何もしない。定期実行）
python ledger/daily.py ingest          # 解かれたページを読み、recall-log.tsv に追記する（定期実行）
python ledger/daily.py show 2026-10-04 # その日のページの正誤とメモを出す（記録しない。解説を書くとき）
python ledger/daily.py pace            # 日付をまたいで解いた日が続いていないか（量を見直す合図）
python ledger/daily.py check           # 一問一答/ の素材と questions.tsv の食い違いを検査（素材を足したら流す）

python ledger/test_tally.py            # tally.py を触ったら流す
python ledger/test_daily.py            # daily.py を触ったら流す
```

### 出力の読み方

- **「確信のある正解」の率が実力。** 見かけの正答率との差が、そのまま水増し分
- **分野別は低いほうから触る。** 高い分野は「今は触らない」であって「安全」ではない
- **逆行の内訳を見る。** 逆行のうち前周で🤔が付いていた割合が過半なら、
  それは忘却ではなく**まぐれの剥落**。解き直しを増やしても直らない
- **混同パターン**は「あなたが実際に取り違えたペア」。解説の肢の表と、想起テストの対比表はここから作る
- **類題が解けても、原題が解けるとは限らない**（統計検定2級では、類題は正解で原題は誤答、が3例あった。類題は手がかりが見えやすい）。直ったかは、原題の解き直し（次の周回）で見る

## 想起テストの記録 `recall-log.tsv`

**一問一答の日替わりページのタップ**（`daily.py ingest`）と `recall-drill` スキル（チャット）が1行ずつ追記する。**手で書いてもよい。**

```
日付	id	結果	確信	形式
2026-09-09	1-01-2	o		対比
2026-09-09	2-01-3	x		反転訓練
```

- 結果: `o` = 正解 / `x` = 不正解
- 確信: `?` = 自信なし / 空 = 確信あり
- 形式: 類題 / 暗記（日替わりページ）／ 対比 / 根拠説明 / 概念 / 反転訓練 / 一問一答（チャット）

### 間隔反復のしくみ

**確信ある連続正解**の回数だけ、次に出るまでの間隔が伸びる（1 → 2 → 4 → 8 → 16 日）。
想起テストで落とすと、その問題は象限が1段昇格して優先度が上がる。

`--next` はこれを加味して出題キューを返す。**キューの順に出す。自分で選び直さない。**

**`--next` と `--drill`（周回の指定なし）は全周回をまとめて見る**（1問ごとに一番新しい着手記録を使う）。
周回ごとの集計（`--round` / `--compare`）は混ぜない。

## 一問一答の日替わりページ（`../一問一答/毎日/`）

形の正本は `project-plan.md` §4「一問一答の形」。ここは仕組みだけ。

| 誰が | 何をする |
|---|---|
| 毎日の定期実行（クラウド） | `daily.py ingest` → `daily.py make` → main に push（指示文は `../docs/一問一答の定期実行.md`） |
| User | pull → 解く（タップと ✍️ メモ）→ push。**連絡はしない** |
| 採点のセッション（PC） | 誤答ごとに類題を `../一問一答/類題/<演習の名前>.md` へ、暗記カードを `../一問一答/暗記カード/<分野名>.md` へ足し、`questions.tsv` に行を足して `daily.py check`。解かれたページを `daily.py show <日付>` で見て、間違えた問いの解説を書く |
| セッションの始め | `daily.py pace`。日付をまたいで解いた日が2日続いていたら、量を減らす案を User に出す |

- **出す順**: 前回落とした → 復習の日が来た（間隔反復）→ まだ出していない。ただし、まだ出していないものを毎日最低 `NEW_MIN` 個は入れる（復習だけで枠が埋まると、その日の誤答から作った類題が何日も出ない）。まだ出していない暗記カードは `questions.tsv` の行の順（弱い分野から入れる）、類題は演習の類題をプレテストの類題より先に、その中で4象限の順に分野を交互に
- **量**: `daily.py` の `DEFAULT_CARDS`・`DEFAULT_RUIDAI` に、立ち上げのときに User と決めた数を書く（解説を読む時間まで含めて決める）
- **`pace` の見方**: ページに最後に書き込んだコミットの、書いた時刻（日本時間）がページの日付より後なら「またいだ」。まだコミットしていないページと、履歴を途中までしか持たない clone（クラウドの定期実行でありうる）では「分からない」と出て、日数に入らない。解かれたページをあとから Claude が直すと、その日も「またいだ」に見えるので、解かれたページは書き換えない
- **記録**: ページの日付で `recall-log.tsv` に入る。同じ日付・同じ問いは1回だけ（何度読み取っても重複しない）。タップの無い問いは記録しない
- **既にあるページは上書きしない。** 古いページを解き残しても、新しいページには同じ問いがまた出る（記録が無いので）
- **ページの冒頭に Claude の所見は置かない**（毎晩書いたが読まれなかった）。✍️ メモへの返事は、間違えた問いの解説の中に書く
- **暗記カードの答えには「⭕ の線」を書く**（どこまで言えたら⭕か。無いと `check` が止める）。線が無いと、迷った問いが全部 ❌ になり、本当に覚えていないカードと区別がつかない
- **「何問出るか」を User に言うときは、`make` せずに並びを確かめてから言う。** 類題を足しても、その日のページに全部は出ない（まだ出していないものの枠がある）
- ページの中の `%%id: …%%` は読み取りに使う行。消さない

## サンプルデータについて

`questions.tsv`・`rounds/`・`../一問一答/` には**動作確認用のサンプル**が入っている。
新しいプロジェクトを始めるときは中身を捨てて、自分の教材に置き換える。
道具の動きを見たいときは、そのまま `python ledger/tally.py`・`python ledger/daily.py check` を叩けば動く。
