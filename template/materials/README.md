# 教材

Claude が生成する学習資料の置き場所。生成の手順は `study-material` スキル。

---

## 4種類だけ。役割が違う

| 種類 | 役割 | いつ作る | 置き場所 |
|---|---|---|---|
| **① 解釈ノート** | 理解する | インプット期 | `materials/{分野名}/` |
| **② 一問一答** | 想起する | 演習期 | ★**`ledger/questions.tsv`**（ここには置かない） |
| **③ 要点シート** | 通読する | 直前2週間 | `materials/要点シート/` |
| **④ 最終圧縮メモ** | 本番直前に見る | 本番の3日前 | `materials/最終メモ.md`（**台帳から自動生成**） |

### ★ ②を独立ファイルにしない — ここが一番大事

一問一答（フラッシュカード）は**別ファイルにせず、演習台帳に直接入れる**。

E資格ではフラッシュカードを495種の md として作り、外部ツールに投入して回した。
よく効いたが、**正答率が一切残らなかった**。学習者の言葉:

> 「フラッシュカードの正答率とかは記録できなかったので、
>  Claude Code でそれを再現できるような良い土台があれば良いなと」

台帳に入れれば、`recall-drill` が**弱点順に出し、間隔反復で回し、正答率を記録する**。
この3つは、教材ファイルを外部ツールに投げる方式では絶対に得られない。

### ④は手で作らない

最終圧縮メモは `python ledger/tally.py --drill` の出力から作る。
**苦手の切り分けデータは台帳側にある。** 手作りすると、その情報を使い損ねる。

---

## ファイル名の規則

**見て意味が分かる日本語名にする。略号を使わない。**

```
✅  materials/確率と統計/確率分布_解釈ノート.md
✅  materials/要点シート/確率と統計_要点.md
✅  materials/最終メモ.md

✗   materials/N3/FC03.md
✗   materials/D5_cheatsheet.md
```

E資格では `FC` `N3` `D5` のような略号を使い、学習者は最後まで
「**FCとかNとかDとか、ファイル名の由来よくわかんなかった**」状態だった。
Claude 内部の都合を、学習者が触るファイル名に持ち込まない。

---

## 解釈ノートのフォーマット

```markdown
# {トピック名}

## 概要
## キーコンセプト     ← 「用語: 定義」形式
## 数式・直感         ← 式 + なぜそうなるかを1段落
## よくある取り違え   ← ★台帳の混同パターンから書く
## 想定Q&A            ← Q: ...? / A: ... 形式
## 試験での出題ポイント
```

**「よくある取り違え」だけは一般論で書かない。**
`python ledger/tally.py` の混同パターン（**この学習者が実際に取り違えた肢のペア**）を見て書く。
一般的な誤解カタログは教材にも外部ツールにもあるが、個人の混同ペアはここにしかない。

---

## 原本は置かない

問題集や書籍の**原本は `.gitignore` で除外**してある（著作物のため）。
台帳の `出典` 列にページ番号だけを持ち、本文は転記しない。

間違えた問題の解説が要るときは、**Claude が公開情報を調べて概念を説明し直す**。
学習者に本から貼り付けさせない（「本当は貼り付けは面倒ですよ」）。
