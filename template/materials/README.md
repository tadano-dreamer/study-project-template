# 教材

Claude が生成する学習資料の置き場所。生成の手順は `study-material` スキル。
**形（雛形・書き方の規則）の正本は `project-plan.md` §4。** ここは置き場所と役割だけ。

---

## 中心は「書く → 読む → 返す」の往復

```
User が解く（解答ノートでタップ・手書きページに途中式・一問一答に ✍️ メモ）
   → Claude が全部読む（どこで取り違えたかを特定する）
   → Claude が解説と図で返す（materials/問題の解説/・materials/図解/）
   → 誤答ごとに類題を足す（一問一答/）→ 次の日のページに出る
```

統計検定2級（3週間・合格）で学習者が次へ持ち出したいと挙げた仕組みは、過去問の解説・図解・一問一答の自動作成で、
どれもこの往復の部品だった。下の表は、その部品の置き場所。

| 種類 | 役割 | いつ作る | 置き場所 |
|---|---|---|---|
| **問題の解説** | 理解する（読み物はこれが既定） | 演習を採点するたび・一問一答で落とすたび | `materials/問題の解説/` |
| **追加解説の図** | 形で見る | チャットで追加解説を頼まれたとき | `materials/図解/`（図は SVG・Claude 用のメモは `追加解説メモ.md` の1枚） |
| **一問一答**（類題・暗記カード） | 想起する | 類題は誤答1つにつき1問・暗記カードは弱い分野から | 問いと答えは `一問一答/`（リポジトリ直下）。★**行と正答率は `ledger/questions.tsv`・`recall-log.tsv`** |
| **最終確認ノート** | 本番前に見る | 本番の約1週間前に Claude から提案 | `materials/最終確認ノート/`（`build.py` が `materials/最終確認ノート.pdf` を作る） |
| 解釈ノート（分野ごと） | 読んで理解する | **作る前に User に聞く**（期間が長いとき） | `materials/{分野名}/` |
| 要点シート | 通読する | 作る前に User に聞く | `materials/要点シート/` |

### ★ 一問一答を台帳から外さない — ここが一番大事

問いと答えの文面は `一問一答/` の md に置くが、**行は必ず `ledger/questions.tsv` に入れ、正答率は `recall-log.tsv` に残す**。
素材と台帳が食い違っていないかは `python ledger/daily.py check` が見る。

E資格ではフラッシュカードを495種の md として作り、外部ツールに投入して回した。
よく効いたが、**正答率が一切残らなかった**。学習者の言葉:

> 「フラッシュカードの正答率とかは記録できなかったので、
>  Claude Code でそれを再現できるような良い土台があれば良いなと」

台帳に入っていれば、日替わりページと `recall-drill` が**弱点順に出し、間隔反復で回し、正答率を記録する**。

### 読み物を2種類にしない

読み物は「問題の解説」が既定。分野ごとの解釈ノートと2本立てにすると、同じ説明が2か所に出て、片方は読まれない
（統計検定2級では解釈ノートを5本作ったが、読まれないまま過去問へ進み、問題の解説に一本化した）。
期間が長く、演習の前に土台から要る分野があるときだけ、**作る前に User に聞いて**作る。

### 最終確認ノートは、台帳の記録から作る

材料は `python ledger/tally.py --drill`（全周回と一問一答の記録から、まだ直っていないものだけを、弱い分野から）。
**苦手の切り分けデータは台帳側にある。** 記憶で作ると、その情報を使い損ねる。
1ページ1トピックで「ひとことで・中身・図・あなたの取り違え・こう出題される」。作り方は `最終確認ノート/build.py` の冒頭。

## ファイル名の規則

**見て意味が分かる日本語名にする。略号を使わない。**

```
✅  materials/問題の解説/過去問1回目_2015年11月_解説.md
✅  materials/問題の解説/一問一答_2026-10-03_解説.md
✅  materials/図解/過去問1回目_2015年11月_問6_ローレンツ曲線.svg

✗   materials/N3/FC03.md
✗   materials/D5_cheatsheet.md
```

E資格では `FC` `N3` `D5` のような略号を使い、学習者は最後まで
「**FCとかNとかDとか、ファイル名の由来よくわかんなかった**」状態だった。
Claude 内部の都合を、学習者が触るファイル名に持ち込まない。

## 追加解説メモ（`図解/追加解説メモ.md`）の形

チャットで追加解説をしたら1節足す（古い順）。解説ファイルは書き換えないので、チャットで説明した中身はここに残す。

```markdown
## YYYY-MM-DD {演習の名前} {問番号} {論点}

図: [[materials/図解/{図の名前}.svg]]

| 項目 | 内容 |
|---|---|
| 問題 | |
| User の言葉 | （言われた言葉のまま） |
| 詰まった所（Claude の見立て） | |
| 説明した要点 | |
| 一問一答への反映 | **未** ／ **済**（どこに足したか） |
```

「一問一答への反映」が **未** のものは、類題・暗記カードを足すセッションが拾い、足したら「済」に直す。

## 解釈ノート（作ると決めたときだけ）

論点ごとに区切り、さっと読める入口にする。メインは演習。

```markdown
# {分野名} — 解釈ノート

| 論点 | 問題 | 状態 |
|---|---|---|
| {論点名} | {問番号} | 🔴 誤解 |

## {論点名}

> [!question] 先に答える
> {狙った誤解を直接突く1問}

> [!success]- 答え（答えてから開く）
> {1行}

- ❌ **思い込み**: 「…」（実際に選んだ肢か、メモがあるときだけ書く）
- ✅ **正しくは**: {規則1行}。$式$ ← {式のすぐ隣に意味}
- 💡 **なぜ**: {1段落}
- ⚖️ **並べて比べる**: {取り違えたペアの表}
- 📌 **試験ではこう出る**: {出題のされ方を1〜2行}
```

**「❌ 思い込み」と「⚖️ 並べて比べる」は一般論で書かない。**
`python ledger/tally.py` の混同パターン（**この学習者が実際に取り違えた肢のペア**）を見て書く。

## 原本は置かない

問題集や書籍の**原本は `.gitignore` で除外**してある（著作物のため）。
台帳の `出典` 列にページ番号だけを持ち、本文は転記しない。
Claude が作った `最終確認ノート.pdf` だけは追跡する（`.gitignore` の例外）。

間違えた問題の解説が要るときは、**Claude が公開情報を調べて概念を説明し直す**。
学習者に本から貼り付けさせない（「本当は貼り付けは面倒ですよ」）。
