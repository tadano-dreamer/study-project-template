# 振り返りフェーズの設計メモ

> 学習が終わったら、**結果が出る前に**これをやる。
> E資格プロジェクトで実際に機能した手順をそのまま型にしてある。

---

## ★ 鉄則: 合否・結果が出る前にやる

**結果を知った後の記憶は、結果に引っ張られる。**
合格すれば全部正しかったことになり、不合格なら全部間違っていたことになる。
だから**結果が入る前に証言を凍結する。**

結果が出たら、書き換えずに**追記**する。追記の観点は3つだけ:

1. 本人の手応え（自己評価）は当たっていたか ← 較正精度。次回の判断材料になる
2. 最大の反省として挙げた項目は、実際に何点分だったか
3. **結果によって変わる結論はあるか** — 原則ない。
   もし変わるものがあったなら、それは**結果に引っ張られているサイン**として疑う

---

## 手順

### 1. 事実台帳を作る（Claude / 半日）

振り返りの前に、**数字と出来事を時系列で並べる**。記憶ではなく記録から。

- 週次の進捗（計画 vs 実績）
- 台帳の全指標（周回ごとの正答率・確信ある正解・逆行率・転換率・分野別）
- 計画変更の日付と、そのとき提示した数字
- 「決めたのに実行されなかった」事象の一覧
- 本人の証言（`project-plan.md` §6 に集めてあるもの）

出力: `retrospective/00_事実台帳.md`

### 2. 設問を作る（Claude / 100問前後）

**配分の目安**（E資格での実績値。これで過不足なかった）:

| 区分 | 割合 | 内容 |
|---|---|---|
| 学習内容そのもの | 25% | 何が身についたか / 本番 / 分野別の実感 / 効いた学習法 |
| **運用・メタ** | **50%** | AI の良かった点・悪かった点 / 分業 / 進捗管理 / 計画 / 教材フォーマット / 機械化 |
| テンプレ化 | 25% | 持ち出すもの・捨てるもの / スキル化候補 / 他分野への一般化 |

**設問の書き方（ここが一番大事）**:

- **すべて記述式。** 選択式にすると、用意した選択肢の中でしか答えが返らない
- **Claude の仮説を書かない。** 「事実: ◯◯」だけを記憶の呼び水として添える。
  仮説を書くと回答がそれに引っ張られる（アンカリング）
- **「わからない・覚えていない」も有効な回答**だと明記する。
  それ自体が「記録が足りなかった」という発見になる
- **数字を添える。** 「D5 が 28% → 69%」のような具体値があると記憶が戻る

出力: `retrospective/01_振り返り_設問.md`

### 3. 回答してもらう

**トグル形式のページ**（Notion 等）に置くと答えやすい。
「順不同でよい」「一気にやらなくてよい」と伝える。

出力: `retrospective/01_振り返り_回答.md` — **原文ママで保存する**（誤変換も直さない）。
解釈は次のステップでやる。一次資料に手を入れない。

### 4. 分析する（Claude）

出力: `retrospective/02_反省まとめ.md`。構成は次の5つ。

1. **結論を先に3つ**
2. **発見** — 各項目に「根拠となる回答 / 何が起きていたか / 次にどうするか」
   - 回答をまたいで**同じ型の失敗**を探す（3件揃えば構造的な問題）
   - 本人が別々のこととして答えているものを**束ねる**のが Claude の仕事
3. ★**答え合わせ** — Claude の仮説がどこで外れたか
   - 設問に仮説を書かなかったからこそ、これができる
   - **外れた仮説は処方が変わる**ので、ここが一番価値がある
4. **設計要求**（P0 / P1 / P2 に分け、出典の設問番号を必ず付ける）
5. **未解決の論点** — 回答の中で矛盾している箇所を、そのまま論点として出す

### 5. 汎用資産を抜き出す

設計要求のうち再利用できるものを、テンプレートとスキルへ落とす。
**具体的な次の1プロジェクトで使うまでが1セット**（作って終わりにしない）。

## 分析のコツ

### 矛盾を潰さない、論点として出す

E資格では「効いたのは NotebookLM」と「NotebookLM 依存を外して」が同居していた。
これは**矛盾ではなく要求**だった（＝「同等以上のものを自作しろ」）。
無理に整合させず、本人に確かめる。

### 「本人が気づいていない束ね方」を探す

- 4件の別々の遅れ → 全部「実力や範囲を測る行為を後ろに置いた」の同じ型
- 3件の別々の「わからない」 → 全部「Claude の内部語彙が届いていない」

**本人はバラバラに答える。束ねるのが分析。**

### 効いた/効かなかったを、効果ではなく摩擦で見る

「効果が実証されているのに実行されなかった」ものは、
説得の失敗ではなく**環境の未整備**であることが多い。
「どこに書くか」が決まっていなかっただけ、というケースが実際にあった。
