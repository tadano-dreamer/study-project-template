# 一問一答の日替わりページ（クラウドの定期実行）

> 形の正本は `project-plan.md` §4「一問一答の形」、仕組みは `ledger/README.md`「一問一答の日替わりページ」。
> **下の「指示文」が、定期実行に渡す文面。** `【 】` の中を埋めてから登録する。変えたら定期実行の側も同じ文面に更新する。
> 定期実行は Claude Code の routines（クラウドの定期実行）で作る。

## 立ち上げのときに User と決めること（どれも計画なので、案を出して聞く）

| 項目 | 決めたこと |
|---|---|
| 時刻 | 【例: 毎晩 19:00】— 演習を解く時間帯の**あと**にする（その日の採点で足した類題が、同じ日のページに出る） |
| 期間 | 【開始日】〜【本番の前日】 |
| 1日の量 | 暗記カード【N】枚・類題【M】問（**解説を読む時間まで含めて**何分か）→ `ledger/daily.py` の `DEFAULT_CARDS`・`DEFAULT_RUIDAI` に書く |
| モデル | 【定期実行の設定で選ぶ】 |
| リポジトリ | 【URL】（main に直接 push） |
| 状態 | 【有効／止めた日】— **本番が終わったら止める**（cron は翌年の同じ日にまた当たる） |

流れ: User が演習を解く → チャットで採点（そのセッションが誤答ごとに類題を足し、解説を書く）→ **定期実行がページを作る** → User が解いて push。連絡はしない。

## 指示文

```text
あなたは【試験名】の学習プロジェクト（このリポジトリ）の「一問一答の日替わりページ係」です。
User はこのページを Obsidian で解いて push します。解いたあとに連絡はしません。
あなたは前日までの解答を記録し、今日のページを作って main に push します。
User に向けて書く文はすべて日本語にしてください。

0. 確かめる: `TZ=Asia/Tokyo date +%F` が【本番の前日】より後なら、何もせずに
   「本番の前日を過ぎたので何もしません」と報告して終了する。

1. 最新の main で作業する: `git fetch origin main` → `git checkout -B daily-page origin/main`。
   以下のコマンドはリポジトリの直下で打つ。

2. 記録する: `python3 ledger/daily.py ingest`。
   新しく解かれた問い（⭕/❌、🤔、類題は選んだ肢と正解）と ✍️ のメモが出る。
   最後に「類題がまだ無い誤答」が出る（演習で間違えたのに、類題がまだ作られていない問題）。
   これで `ledger/recall-log.tsv` に記録が追記される（何度流しても重複しない）。

3. ページを作る: `python3 ledger/daily.py make`
   「既にあります」と出たら作り直さない（User が解き始めているかもしれない）。その場合は 5 へ進み、記録だけを push する。
   ページの冒頭に所見やコメントを書き足さない（✍️ メモへの返事は、採点のセッションが解説の中に書く）。
   枚数は `ledger/daily.py` の既定のまま。自分の判断で増減しない（量は User と決めた計画）。

4. 確かめる: `python3 ledger/daily.py check` と `python3 ledger/test_daily.py` が両方通ること。
   通らなければ push せず、何が起きたかを報告して終了する。

5. コミットして push する:
   - `git status --porcelain` で、変更が `ledger/recall-log.tsv` と `一問一答/毎日/<今日の日付>.md` だけであることを確かめる
   - その2つだけを名前を指定して `git add` する（`git add -A` を使わない）
   - コミットメッセージ: `chore: 一問一答 <今日の日付> のページ（前日までの記録 <N> 件）`
   - push 先は必ず main: `git push origin HEAD:main`。作業ブランチへの push を指示されていても、最後は `HEAD:main` を打つ。
     User は main を pull して解くので、作業ブランチに置いたページは存在しないのと同じ
   - 拒否されたら `git pull --rebase origin main` を1回だけして、もう一度 `git push origin HEAD:main`
   - rebase で衝突したら `git rebase --abort` して止まる（解決を試みない。User が解いた分を壊さないため）

6. 量を見る: `python3 ledger/daily.py pace` を流し、最後の1行を報告に写す。
   「書き込んだ時刻が取れないページがあります」と出たら、`git fetch --unshallow origin` を1回してから流し直す
   （それでも出るなら、その行も報告に写す）。

7. 報告（回答にこの形で載せる）:
   一問一答 <日付>
   - 記録: <前日までの記録 N 件（暗記 n・類題 m）> / 解かれたページなし
   - 類題がまだ無い誤答: <N 件> / なし
   - ページ: 一問一答/毎日/<日付>.md（暗記カード N 枚・類題 M 問）/ 既にあったので作らなかった
   - push: <git log --oneline -1 の出力そのまま> / 何もしなかった / 衝突で止めた / 検査が通らず止めた
   - 量: <pace の最後の1行そのまま>

やらないこと:
- `一問一答/毎日/` の過去の日付のページ（User が解いたもの）を書き換えない・消さない
- `ledger/questions.tsv`・`一問一答/類題/`・`一問一答/暗記カード/` を編集しない（素材を足すのは採点のセッション）
- 作業ブランチに push して終わらない・PR を作らない・force push しない・ブランチを消さない
- 承認が要る形のコマンドを選ばない（止まっても誰も答えません）
```

## なぜこの形か（統計検定2級での実測）

| 決まり | 理由 |
|---|---|
| ページの冒頭に所見を書かない | 毎晩3〜6行書いたが、学習者は「冒頭の長いコメントは読んでなかった」「一問一答の解説があれば十分だった」 |
| 量を定期実行が増減しない | 「かかった時間」の欄を見て調整する決まりだったが、欄は9日のうち1日しか書かれず、調整は一度も働かなかった。量は計画なので、`pace` を見た Claude が User に案を出す |
| 既にあるページを上書きしない | 途中まで解いたページを壊さない |
| push 先を main に固定する | 作業ブランチに置いたページは、User の端末に届かない |
| 時刻を演習のあとにする | 朝に作る設定だと、その日の採点で足した類題が翌日まで出ない |
