# 学習プロジェクト テンプレート

資格試験・語学・業務スキルなど、**期限のある学習を Claude Code と一緒に走らせる**ための
プロジェクト雛形とスキル一式です。

E資格（JDLA Deep Learning for ENGINEER）を **16週間・遅れ0日**で完走し、**合格**した実プロジェクトの
振り返り（一問一答100問）から、再利用できる部分だけを抜き出して作りました。
「うまくいったからそのまま」ではなく、**失敗した4か所を構造で潰した形**になっています。

そのあと、このテンプレートで**統計検定2級を3週間で受けて合格**し、その振り返り（41問）で直した点を入れてあります
（2026-11）。効いた部品（問題の解説・手書きページ・一問一答の日替わりページ）を足し、
読まれなかった文章と、誰も見ていなかった記録の欄を直しました。

## 5分で始める

```bash
# 1. 新しい学習プロジェクトのフォルダを作り、雛形をコピー
cp -r <このリポジトリ>/template  ~/study-<試験名>
cd ~/study-<試験名> && git init

# 2. スキルを Claude Code に入れる（初回だけ）
powershell -NoProfile -ExecutionPolicy Bypass -File <このリポジトリ>/install.ps1

# 3. Claude Code を起動して、こう言う
#    「◯◯試験の勉強を始めたい」
```

`study-project` スキルが起動し、**初日ゲート**（下記）から立ち上げが始まります。

> 📖 **初めて使うなら [docs/00_はじめかた.md](docs/00_はじめかた.md) を読んでください**（1画面）。
> 何を自分で用意するか・初日に何が起きるか・毎週何をするかが書いてあります。

### すでに勉強を始めている人へ

丸ごと乗り換える必要はありません。**走行中でも今日から効くもの**（出題範囲の照合・
確信度つきの記録）と、**立ち上げ時にしか意味がないもの**があります。
仕分け表とコピペ用のプロンプトを
**[docs/04_既存プロジェクトへの部分導入.md](docs/04_既存プロジェクトへの部分導入.md)**
に置いてあります。

## このテンプレートが前提にしている6つのこと

詳細と根拠は **[docs/01_設計思想.md](docs/01_設計思想.md)**。ここでは結論だけ。

### 1. 人間が見る画面は「ガント・学習ページ・今週やること」の3つだけ

E資格では計画書・STATUS・TODAY・弱点表と5階層のドキュメントを作りましたが、
学習者が実際に見ていたのは**ガントだけ**でした（STATUS は「全然読んでいない」）。
一方でガントは「**進捗を一瞥で見るのに役立った。行動を変えた**」と明言されています。
統計検定2級でも同じで、毎晩書いたページ冒頭の所見は「読んでなかった」。
読まれるかどうかは、中身ではなく**置き場所**で決まっていました。

→ 数字と信号はガントに、所見は問題の解説の中に書く。他のファイルは AI の内部状態と割り切る。

### 2. 「地図」と「現在地」を初日に作る

E資格の最大の失敗はここでした。

| やるべき時期 | 実際 |
|---|---|
| 出題範囲（シラバス）との照合 | **受験前日** |
| 教材の目次を機械可読にする | **開始から2か月後** |
| 初見の実力測定 | **本番7日前** |

本番で範囲改訂の新規項目が10問前後出て、対応できたのは1つだけ。
シラバス照合は**30分で終わる作業**でした。

→ **初日ゲート**を置き、ここが埋まるまで教材生産に進みません。

### 3. 確信度を1問目から取る

正誤だけの記録は実力を水増しします。E資格では2周目で
「1周目に正解した問題の36%を落とす」という現象が起き、原因は忘却ではなく
「**1周目がまぐれだった**」ことでした。まぐれを見つける仕組みが遅すぎたのです。

→ 台帳は **正誤 × 確信の4象限**で管理します。

|  | 確信あり | 確信なし 🤔 |
|---|---|---|
| **正解** | ✅ 定着 | ⚠️ **たまたま正解**（本番で落とす最有力候補） |
| **不正解** | 🔴 **誤解**（知識が間違っている） | ⬜ 未学習 |

### 4. 守らせたい作法は、全部「数字」に変換する

「注意しよう」「声に出そう」は効きません（実証済み）。一方、
遅延日数・必要ペース・正答率のような**数字は行動を変えました**。

→ 例: 「最も不適切なものを選べ」型で落とす癖は、注意喚起ではなく
**設問タイプ別の正答率**として集計し、想起テストに混ぜて潰します。

### 5. 学習の中心は「書く → 読む → 返す」の往復

統計検定2級で学習者が次へ持ち出したいと挙げた上位3つは、過去問の解説・図解・一問一答の自動作成でした。
学習者が書いたもの（手書きの途中式・メモ）を Claude が**全部読み**、どこで取り違えたかを特定して、解説と図で返す。
手書きページを読むことは「**これ1番重要ですね**」と言われています。

→ 採点のたびに、聞き直さなくて済む深さの解説をファイルに書く。小問ごとに手書きページを用意する。
一問一答のページは定期実行で毎日作り、学習者は pull → 解く → push だけ。

### 6. 計画は聞く。中身は聞かずに進める

「**学習内容など事実は進めて良かった。計画周りは聞いて欲しい**」。
日程・1日の量・時刻・作る教材の種類・買う物は、Claude が案を出して聞きます。解説・図・採点・分析は聞きません。
「任せる」と言えば計画も決めて実行し、「まず計画だけ」と言えば案を1つ出して止まります。

→ 量のように「決めたあと誰も見ていなかった」ものは、記録（push の時刻）を見て Claude から見直しの案を出します。

## 台帳の使い方（最短）

```bash
python ledger/tally.py                 # 4象限・分野別・設問タイプ別・混同パターン
python ledger/tally.py --compare 1 2   # 逆行率・転換率
python ledger/tally.py --next 15       # 次に出す問題（間隔反復を加味）
python ledger/tally.py --recall        # 想起テストの通算成績
python ledger/tally.py --drill         # 直前の教材の材料（まだ直っていないものだけ）
python ledger/daily.py make            # 一問一答の今日のページを作る
python ledger/daily.py pace            # 日付をまたいで解いた日が続いていないか（量を見直す合図）
python ledger/手書き/tools/gen_pages.py --round 1 --link   # 小問ごとの手書きページを作る
```

解答は Markdown のチェックボックスをタップするだけです。**正誤は自動判定**されるので、
❌ を手で付ける必要はありません（付け忘れが起きるため、意図的にそうしています）。

```markdown
## 1-01 用語と計算の基本

### (1)
- [ ] A
- [x] C          ← 選んだ肢だけタップ
- [ ] D
- [x] 🤔 自信なし  ← 自信がなければタップ
```

iPad / スマホから触る前提の形式です。詳細は [template/ledger/README.md](template/ledger/README.md)。

## 想定していること・していないこと

**向いている**: 一問一答が大量にある資格試験。期限が決まっている。ひとりで進める。
**正解が手元にある選択式の試験**だと、Claude が取り違えを特定しやすく、解説の往復がよく回ります。

**要るもの**: 手書きページは Obsidian と Excalidraw プラグイン（タブレットで書く）。
一問一答の日替わりページは Claude Code のクラウドの定期実行。どちらも使わずに、台帳とガントだけでも動きます。

**そのままでは足りない**: 試験のない学習（業務スキル・語学の実運用など）。
この場合は**ゴールと KPI を最初に決める**必要があります。仕組み自体は成立します。

**外して使う**: このリポジトリは Windows + 日本語環境で作られています。
`.ps1` まわりは環境依存なので、他OSでは `render-gantt-png.ps1` を
`chrome --headless --screenshot` の同等コマンドに読み替えてください。
