# 初日ゲート — 立ち上げチェックリスト

**この3つが埋まるまで、教材を1文字も書かない。**
根拠は [01_設計思想.md](01_設計思想.md) 判断2。所要は合計で2〜3時間。

---

## ゲート1 — 出題範囲の一次資料を確保する

- [ ] 主催者の**公式**シラバス／出題範囲表を入手した（二次情報の要約で代用しない）
- [ ] **改訂の有無を確認した。** 「今年から追加された項目」「削除された項目」を列挙した
- [ ] 出題形式を確認した（問題数・時間・合格ライン・選択式か記述式か・電卓の可否）
- [ ] 手に入らないものがあれば、それを `project-plan.md` にリスクとして書いた

> E資格では、これを**受験前日**にやった。本番で改訂の新規項目が10問前後出て、
> 対応できたのは1大問だけ。**30分で終わる作業**だった。

**成果物**: `docs/範囲と教材.md` の「出題範囲」節

---

## ゲート2 — 範囲と教材を機械可読な目次にする

- [ ] 出題範囲を**分野リスト**に落とした（後で台帳の「分野」列になる）
- [ ] 使う教材をすべて列挙した（問題集・講座・書籍・過去問）
- [ ] **各教材の目次を全部取った。** 動画講座なら講座番号まで
- [ ] 分野リストと教材を対応づけた（**教材が0件の分野**があれば印をつける）

> E資格では、動画講座の目次（全358講座）を作ったのが**開始から2か月後**だった。
> それまで進捗を「何番まで見た」で受け取れず、学習者が毎回説明する手間が発生していた。
> 学習者の証言: 「講座数と講座番号を伝えるのに苦労しました。
> **あなたが講座のメタ情報を把握するのが遅かったです**」

**成果物**: `docs/範囲と教材.md` の「教材の目次」節と対応表

---

## ゲート3 — プレテストで現在地を測る

- [ ] 全範囲から**薄く広く 20〜30問**を選んだ（1分野あたり2〜3問でよい）
- [ ] 学習者が解いた
- [ ] **確信度つき**で台帳に記録した（`ledger/rounds/round0/`）
- [ ] `python ledger/tally.py --round 0` で4象限と分野別を出した

> ここが**全ての優先順位の根拠**になる。これが無いまま計画を引くと、
> 「どの分野が苦手か学習者自身も分からない」まま最後まで走ることになる。
> E資格の証言: 「**どの分野が苦手、とかは自分では意識してなかった**」

**成果物**: `ledger/` の初期データ + 分野別の弱点順リスト

---

## ゲート通過後 — WBS を引く

3つ埋まってから、初めてガントを作る。**ゲートの成果物が WBS の材料**だから。

- [ ] `wbs-gantt_v1.html` の CONFIG（`PROJECT` / `START` / `GOAL` / `TODAY`）を埋めた
- [ ] Phase 0 に初日ゲートを置き、`st:"done"` にした
- [ ] Phase 1 以降を、**プレテストで弱かった順**に並べた
- [ ] **中間ゲートを置いた**（「◯月◯日終了時に累計△問」のような機械判定できる形）
- [ ] 中間ゲートに**未達だったときの縮退案**を1行書いた
- [ ] PNG を生成して描画を確認した

---

## 立ち上げ時に学習者へ聞くこと

**まとめて1回で聞く**（小出しにしない）。

1. **本番日（締切）** と、逆算の起点にする日
2. **可処分時間**の実態 — 平日/休日それぞれ何時間、どの端末で、どこで
3. **教材** — 既に持っているもの / これから買うもの
4. **合格ライン**と、それを測る手段（過去問・模試の有無）

---

## ゴールの書き方

`project-plan.md` の冒頭に**ゴールを1つ**書く。複数あるなら:

- 優先順位を明記する
- **捨てる順番を先に決めておく**
- 捨てるときは「いつやるか」まで書く（「捨てた」ではなく「Phase 2 へ送った」）

> E資格ではゴールが2つあり、途中で片方をスコープアウトしたのに
> ゴールの記述を書き換えなかった。振り返りでその部分は「未達」として自己評価された。
> **判断は正しかったのに、看板を下ろさなかったせいで失敗に見えた。**
