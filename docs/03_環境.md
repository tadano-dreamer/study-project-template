## モバイル同期の構成（そのまま持っていってよい成功資産）

```
  Claude Code (Windows PC)
        │  commit / push
        ▼
     GitHub  ──────────────────────► ガント PNG をブラウザで閲覧（スマホ可）
        │  pull（Working Copy）
        ▼
     iPhone  ──► iCloud フォルダ ──► iPad の Obsidian で問題を解く
                                          │
                                          └─► チェックボックスをタップ → commit
```

**評価**（E資格の学習者）:
- 「このアーキテクチャは**とても満足していました**」
- 「Claude がコードを実行できない制約は**ほとんど足を引っ張らなかった**」
- 「ガント PNG は **GitHub からパッと見ることができました**」
- 「これは良かった。**ぜひ今後もやる**」

### 押さえる点

1. **ガントは必ず PNG も生成する。** スマホの GitHub は JavaScript を実行しないので、
   HTML のままではグラフが見えない
2. **`.ipynb` は既定で `.gitignore`。** スマホの Git クライアントで壊れ、
   削除済みファイルがステージングに残り続けた。追跡が要るときだけ明示的に外す
3. **クロスプラットフォームで同期するファイルは ASCII 名にする**
   （日本語名は下記 NFC/NFD 問題を踏む）

## Windows + 日本語環境の落とし穴

このテンプレートは Windows 11 / Git Bash / Windows ネイティブ Python で作られている。
以下は**繰り返し踏んだもの**なので、コードを書く前に避けること。

| 症状 | 原因 | 対策 |
|---|---|---|
| `SyntaxError: unicodeescape` | Python 文字列に `C:\Users\...` を直書き | raw 文字列 `r'...'` か `/` 区切り |
| 出力が `???{??` に化ける | stdout が cp932 | `sys.stdout.reconfigure(encoding='utf-8')` |
| 日本語ファイルで `UnicodeDecodeError` | `open()` の既定が cp932 | `encoding='utf-8'` を必ず明示 |
| `/tmp/...` が `FileNotFoundError` | python/node が Windows ネイティブで Git Bash のパスを解決できない | `C:/...` 形式の絶対パスを渡す |
| PowerShell で `&&` がパースエラー | PS 5.1 に `&&` はない | `A; if ($?) { B }` |
| PowerShell で exit 0 なのに失敗扱い | native exe に `2>&1` を付けた | `2>&1` を外す |

### ★ `.ps1` にはコメントも含めて ASCII しか書かない

**症状**: `.ps1` の先頭に日本語コメントを置いたら、**エラーも出さずに途中で処理が止まった。**
構文チェックは「OK」を返すのに実行だけ失敗する。ASCII に書き換えたら即解決した。

**原因**: 多くのエディタは `.ps1` を BOM なし UTF-8 で保存する。
Windows PowerShell 5.1 は BOM なしファイルを**システムの ANSI コードページ（日本語環境では CP932）**
として読むため、日本語コメントのバイト列が化けて実行を阻害する。
**同じ日本語コメントでも壊れるファイルと壊れないファイルがあり、再現条件が不安定**なのが厄介。

**対策**: 実行系の `.ps1` はコメントも ASCII で書く。説明は `.md` 側に日本語で残す。
このテンプレートの `.ps1` は全部そうしてある。

### ★ 日本語ファイル名の NFC/NFD 二重登録

**症状**: 同名に見えるファイルが Git に**2つ**登録され、iPhone の Git で差分が出続けた。

**原因**: 濁点の表現が **NFD（`テ` + 結合濁点）と NFC（`デ`）で別ファイル**として登録されていた。
macOS/iOS はファイル名を NFD 正規化するため、NFC 名の追跡ファイルを常に「変更あり」と誤検知する。

**対策**: **クロスプラットフォームで同期するファイルは ASCII 名にする。**

### ★ 全角括弧を含むパスで Read/Bash が失敗する

`（）` を含むパスは `ls` では見えるのに `Read` や `cp` が "File does not exist" になる。
シェル経由のパス展開で UTF-8 の正規化問題が起きる。

**対策**: PowerShell の `-LiteralPath` を使う、もしくはワイルドカードでシェルに解決させる。

### ★ ヒアドキュメント経由の Python パッチでエスケープが二重に解ける

Bash のヒアドキュメント（`<<'EOF'`）越しに Python スクリプトを渡すと、
文字列内の `\n` `\t` が**実際の改行・タブに展開されてしまう**ことがある
（クォート付きデリミタでも起きた）。

**対策**: **長いスクリプトはファイルに書いてから実行する。** ヒアドキュメントで済ませない。

## 大きい JSON / ノートブックの扱い

- 出力画像の base64 を含む `.ipynb` は数百KB〜MBになり、読み込みが上限に当たる
- 対策: PowerShell の `ConvertFrom-Json` か Python で cell 単位に分解して扱う
- `jq` はこの環境に入っていない前提で書く

## クローンしたリポジトリ

サブディレクトリとして他のリポジトリを置くときは、**必ず `.git` も削除する**。
履歴が数百MBを占め、ファイルを消しても容量が減らない。

```bash
rm -rf <cloned>/.git <cloned>/.github
```
