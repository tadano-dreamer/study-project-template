# study-init — 立ち上げ（初日ゲートが本体）

テンプレート実体: `{{TEMPLATE_REPO}}/template/`

## ★ 最重要 — 初日ゲートを通すまで、教材を1文字も書かない

E資格プロジェクトで最大の反省がここ。**「地図」と「現在地」を両方とも最後に作った。**

| 本来やるべき時期 | 実際にやった時期 |
|---|---|
| 出題範囲（シラバス）との照合 | **受験前日** |
| 教材の目次を機械可読にする | **開始から2か月後** |
| 初見の実力測定 | **本番7日前** |

結果、本番で範囲改訂の新規項目が10問前後出て、対応できたのは1つだけだった。
**シラバス照合は30分で終わる作業**で、初日にやっていれば16週間の優先順位が全部変わっていた。

だから、この順序は動かさない。

### ゲート1: 出題範囲の一次資料を確保する

- 主催者の公式シラバス・出題範囲表・改訂履歴を**必ず一次情報で**取る（WebFetch/WebSearch を使う）
- **改訂の有無を確認する。** 「今年から追加された項目」「削除された項目」を明示的に列挙する
- 手に入らなければ、そのこと自体を `project-plan.md` にリスクとして書く

### ゲート2: 範囲と教材を機械可読な目次にする

- 出題範囲を**分野リスト**に落とす（後で台帳の「分野」列になる）
- 使う教材（問題集・講座・書籍）の**目次を全部取る**。
  動画講座なら講座番号まで。ここを作らないと、後で進捗を「何番まで見た」で受け取れない
- **問題ごとの、教材の実際のページ**も取る（解答ノートの各問に書く。目安のページだと、解き直しのときに問題を探す手間になる）
- 出力先: `docs/範囲と教材.md`

### ゲート3: プレテストで現在地を測る

- **20〜30問**でよい。全範囲から薄く広く
- **確信度つき**で `ledger/` に記録する（→ `drill-ledger`）
- これが**全ての優先順位の根拠**になる。ここが無いまま計画を引くと、
  「どの分野が苦手か User 自身も分からない」状態のまま16週間走ることになる

### ゲート通過の判定

3つとも埋まったら、初めて WBS を引く。埋まらない項目があるなら、
**その項目を Phase 0 のタスクとしてガントの先頭に置き、期限を切る。**

## 生成するファイル

`{{TEMPLATE_REPO}}/template/` を新プロジェクトのフォルダへコピーし、以下を埋める。

| ファイル | 誰のためか | 中身 |
|---|---|---|
| `wbs-gantt/wbs-gantt_v1.html` | **人間** | CONFIG を埋める。Phase 0 に初日ゲートを置く。**「直前の教材を提案」の行を、本番の約1週間前に置く** |
| `THIS-WEEK.md` | **人間** | 今週やること。**まだやっていない行が先頭、済んだ行は末尾の畳んだ枠** |
| `ledger/rounds/round1/` | **人間が触る記録先** | 解答ノート。各問に教材のページ（📖）と手書きページへのリンク（✏️） |
| `ledger/手書き/` | **人間が書く** | 小問ごとの手書きページ（`gen_pages.py --round 1 --link`）。既定は「あり」 |
| `一問一答/` | **人間が解く** | 類題と暗記カードの素材。日替わりページは定期実行が作る |
| `project-plan.md` | AI | ゴール・KPI・期間から決めたこと・教材の形・進捗ログ・§6 の発言の記録 |
| `STATUS.md` | AI | 状態の圧縮スナップショット。毎セッション更新 |
| `ledger/questions.tsv` | AI | 問題マスタ |
| `CLAUDE.md` | AI | プロジェクト固有のルール |
| `docs/範囲と教材.md` | AI | ゲート1・2の成果物 |
| `docs/一問一答の定期実行.md` | AI | 定期実行に渡す指示文（`【 】` を埋めて登録する） |

> 人が見る画面は、ガント・学習ページ（解答ノート・解説・図・一問一答）・`THIS-WEEK.md` の3つだけ。
> `STATUS.md`・`project-plan.md` は2回のプロジェクトで一度も開かれていない。User に伝えたいことは、3つのどれかに書く。
> `TODAY.md` は作らない（E資格で日単位に作ったが、初期しか見られなかった）。

## ゴールの書き方（後で効く）

`project-plan.md` の冒頭に**ゴールを1つだけ**書く。複数あるなら優先順位を明記し、
**「捨てる順番」も先に決めておく**。

E資格ではゴールが「合格 + PyTorch で実装できるようになる」の2つあり、
途中で後者をスコープアウトしたのに**ゴールの記述を書き換えなかった**。
結果、後者は「未達」として残った。捨てるときは「いつやるか」まで書けば、
未達ではなく次フェーズへの送りになる。

## 立ち上げ時に User へ確認すること

決め打ちせず聞く。ただし**まとめて1回**で聞く（小出しにしない）。

1. **本番日（締切）と、逆算の起点にする日**
2. **可処分時間**の実態（平日/休日、どの端末で、どこで）
3. **教材**は何を使うか（既に持っているもの / これから買うもの）
4. **合格ライン**と、それを測る手段（過去問・模試の有無）

### プレテストのあと、計画を発行する前に聞くこと（期間から決める）

**計画（日程・量・時刻・作る教材の種類・買う物）は、Claude が案を出して User に聞く。中身（解説・図・採点・分析）は聞かずに進める。**
「任せる」と言われたら計画も決めて実行し、「まず計画だけ」と言われたら案を1つ出して止まる（`CLAUDE.md`「Claude が守ること」9）。

次の6つは、期間の長さで答えが変わる。**前のプロジェクトの運用を既定にしない**
（統計検定2級は3週間で、学習者は5つの運用について「今回は時間がなかったから」と断っている）。
案を1つずつ添えて聞き、答えを `project-plan.md` §3「期間から決めること」に書く。

| 聞くこと | 案を作るときの材料 |
|---|---|
| 分野ごとのノート（解釈ノート）を作るか | 短期なら作らず、読み物は問題の解説だけ。長期で、演習の前に土台から要る分野があれば、その分野だけ |
| 周回数 | 短期は2周＋任意の3周目。長ければ4〜5周 |
| 予備の教材を買うかを、いつ・何の線で判定するか | 1周目の途中に、正答率の線を先に決める（判定は機械的に、決めるのは User） |
| 一問一答の1日の量と、定期実行の時刻 | **解説を読む時間まで含めて**何分か。時刻は演習を解く時間帯のあと |
| 手書きページ | 既定は「あり」。要らない種類の問題があるか |
| 直前の教材を提案する日 | 本番の約1週間前（2周目が終わるところ）。ガントに行を置く |

**ガントは、Claude が決めた部分を全部見せてから発行する**（空いた日の埋め方・中間ゲートの基準と縮退案・期日の前倒し）。
User が日程を詰めて空けた日は、バッファの意図を疑い、作業で埋めない。

## 前の振り返りで直した形を確かめる（`project-plan.md` §7 に写す）

このテンプレートには、前のプロジェクトの振り返りで直した形が入っている。**直した形が効いたかは、使ってみるまで分からない。**
立ち上げのときに、下の表を新しいプロジェクトの `project-plan.md` §7 に写す。振り返りで1行ずつ結果を書き、テンプレートへ戻す
（効かなかった形は直し、効いた形はこの表から外す）。

| 直した形（統計検定2級の振り返り・2026-10） | どう確かめるか |
|---|---|
| `THIS-WEEK.md` を「まだやっていない行が先頭・済んだ行は畳んだ枠」にした（2回続けて開かれなかった） | 振り返りで「開いたか・何のために」を聞く。開かれなければ、やめてガントに寄せる |
| 計画は聞く・中身は聞かない、の表を `CLAUDE.md` に置いた | 振り返りで「聞いてくる量とタイミング」を聞く。§6 に「聞いてほしかった」「聞かなくてよかった」が何行あるか |
| 一問一答の量を始めに決め、日付をまたいだ日が2日続いたら減らす案を出す | `python ledger/daily.py pace` の結果と、Claude が案を出した日が §5 にあるか |
| ページ冒頭の所見をやめ、✍️ メモへの返事を解説の中に書く | 振り返りで「メモへの返事は届いていたか」を聞く |
| 暗記カードの答えに「⭕ の線」を書く | 暗記カードで 🤔（あいまいな正解）が使われた回数（`recall-log.tsv` の `確信` 列）。前回は、学習者の申告で「ほぼ使ってない」 |
| 直前の教材を、本番の約1週間前に Claude から提案する | 提案した日が §5 にあるか。本番の朝に何を見たかを聞く |
| `tally.py --drill` が全周回と一問一答の記録をまとめる | 直前の教材の材料を、使い捨てのスクリプト無しで出せたか |
| 本番の報告を受けた返事で3つ聞く | §6 に、本番当日の答えが残っているか |
| 振り返りを40問前後・チャットで1問ずつにした | 最後の設問で、振り返りの形そのものを聞く |
| 解答ノートの各問に教材の実際のページを書く | 振り返りで「問題を探すのに困ったか」を聞く |
