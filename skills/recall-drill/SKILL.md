# recall-drill — 想起テスト

台帳: `ledger/`（`tally.py` / `questions.tsv` / `recall-log.tsv`）

## このスキルの存在理由

E資格プロジェクトでは、学習効果の主エンジンは **NotebookLM** だった。
User が「効いた」と挙げた理由はほぼ全部そこに帰着する — 比較概念の表・
「こう出題される / こんな誤解がある」の提示・聞き返せること。

その User が「**依存は外してほしい。ただし NotebookLM の機能を上回る価値を出すこと**」と
条件をつけた。だから**同じことをやるだけでは不足**で、向こうに構造的に作れないものを出す。

### 向こうにできないこと＝ここでやること

| | 教材から作る道具 | **このスキル** |
|---|---|---|
| 出題順 | 教材にある概念を等確率で | **台帳の4象限で優先度づけ**（🔴誤解 → ⚠️たまたま正解 → ⬜未学習 → ✅定着） |
| 対比表 | 教材にある一般的な対比 | ★**あなたが実際に取り違えた肢のペア**から作る |
| 誤解の指摘 | 「よくある誤解」 | ★**あなたが自信を持って間違えた記録**そのもの |
| 反復 | 毎回ゼロから | **間隔反復**（確信ある連続正解ごとに 1→2→4→8→16日と寝かせる） |
| 正答率 | 残らない | **`recall-log.tsv` に残り、次の出題順を変える** |
| 出題形式 | 一定 | **象限ごとに変える**（下記） |

> 「正答率が記録できなかった」は E資格で User が名指しした唯一の明確な欠落。
> ここを埋めないなら、このスキルを作る意味はない。

## 手順

### 1. 出題キューを取る

```
python ledger/tally.py --next 15
```

出題候補・寝かせ中の件数・各問の象限と最終出題日が出る。**ここに出た順で出す。**
自分で選び直さない（弱点優先の順序は台帳が決める）。

### 2. 事前に調べておく（★E資格でできていなかったこと）

🔴誤解 が付いている問題のキーワードは、**出題する前に公開情報を調べておく**
（WebSearch / WebFetch）。User に解説を貼らせるのではなく、Claude 側が先に用意する。

> E資格では、間違えた問題の解説を User が本から手で貼り付けていた。
> User の言葉: 「本当は貼り付けは面倒ですよ」「あなたのリサーチ機能をうまく
> 活用できてなかったですね」。**リサーチはこのループの中に入れる。**

著作権に配慮し、教材の本文は転記させない。**公開情報で概念を説明し直す。**

### 3. 象限ごとに出題形式を変える

同じ「問題を出す」でも、処方が違う。

| 象限 | 何が壊れているか | 出し方 |
|---|---|---|
| 🔴**誤解** | 知識そのものが間違っている | **混同ペアで出す。**「XとYの違いを1文で」「あなたは前回 `A` を `C` と答えた。その2つは何が違うか」 |
| ⚠️**たまたま正解** | 当たったが根拠がない | **根拠を言わせる。**「なぜその答えなのか。他の3つがなぜ違うのかを1つずつ」 |
| ⬜**未学習** | まだ触れていない | 概念から。定義 → 直感 → 一番出やすい形 |
| ✅**定着** | 保持の確認 | 間隔反復。素直に一問一答 |

**答えは先に見せない。** 想起（思い出す行為）そのものが効くので、
選択肢すら出さずに「言葉で説明して」から入るほうが強い場面が多い。

### 4. 設問反転を訓練に混ぜる

`tally.py` の「設問タイプ別」で **誤選択型（「最も不適切なものを選べ」）の正答率が
10pt 以上低い**なら、**意図的にその型で出す**。

E資格では、この型の対策を決めた**後**に同じ型でまた落とした。User の総括は
「スピードを出して解いていたから意識できなかった」「声に出すとかは効果ない。
**仕組みで解決したい**」。

だから「注意しよう」とは言わない。**出題に混ぜて、正答率という数字にする。**
数字になれば行動が変わることは、このプロジェクトで実証済み。

### 5. 判定と解説

- 正誤を告げる
- **必ず対比表を出す**（混同した2つを並べる。3行でいい）
- 「試験ではこう出る」を1行
- User が「わかった」と言っても、**その場で確信度を聞く**（🤔かどうか）

### 6. 記録する（ここを飛ばさない）

`ledger/recall-log.tsv` に1行追記する。TSV・UTF-8・追記のみ。

```
日付	id	結果	確信	形式
2026-09-09	1-01-2	o		対比
2026-09-09	2-01-3	x		反転訓練
```

- 結果: `o` = 正解 / `x` = 不正解
- 確信: `?` = 自信なし / 空 = 確信あり
- 形式: 対比 / 根拠説明 / 概念 / 反転訓練 / 一問一答

**この1行を書かないと、次回の出題順が変わらない。** 記録がスキルの本体。

### 7. セッションの締め

```
python ledger/tally.py --recall
```

- 今日の成績（何問中何問・確信ある正解は何問）
- 「何度出しても落ちる問題」が出ていたら、**出題を増やしても直らない**ので、
  教材側を作り直すか、捨てる判断を User に提示する
- 次回の予定（間隔反復でいつ何が戻ってくるか）を1行で

## やらないこと

- **答えを先に見せる**（想起の効果が消える）
- **台帳に記録せずに出題する**（一番やりがちで、一番もったいない）
- **User が正解した問題を褒めて終わる**（確信度を聞かないと、たまたま正解が見えない）
- **一度に大量に出す**（15問前後が上限。それ以上は記録の質が落ちる）
