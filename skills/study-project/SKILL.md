# study-project — 学習プロジェクトの入口

このスキルは**振り分け役**。実作業は下の専用スキルが持つ。
出典となるテンプレートは `{{TEMPLATE_REPO}}` にある。**まずそこの `README.md` を読む。**

## 設計の前提（ここを外すと全部崩れる）

E資格（2026-05-10 〜 08-30 / 16週）と統計検定2級（2026-09-23 〜 10-11 / 3週）の実測にもとづく。根拠は
`{{TEMPLATE_REPO}}/docs/01_設計思想.md`。要点は6つ:

1. **人間が見る画面は、ガント・学習ページ・`THIS-WEEK.md` の3つだけ。** STATUS・進捗ログ・計画書は
   AI の内部状態であり、User に読ませる前提で作らない（2回とも一度も開かれていない）。
   数字と信号はガントに、所見は問題の解説の中に書く。
2. **「地図」と「現在地」を最初に作る。** 出題範囲の一次資料と、プレテストによる実力測定。
   ここが埋まる前に教材を作り始めてはいけない（→ `study-init`）。
3. **確信度を1問目から取る。** 正誤だけの記録は実力を水増しする（→ `drill-ledger`）。
   一問一答は**台帳から外さない**（問いの文面は md に置いても、行は `questions.tsv` に入れる）。
   そうしないと正答率が残らない（→ `study-material`）。
4. **User を動かすのは数字。** 「注意しよう」は効かない。守らせたい作法は、
   すべて「測って数字にする」へ変換する。
5. **学習の中心は「User が書く → Claude が全部読む → 解説と図で返す」の往復。**
   手書きの途中式と ✍️ メモを読み、どこで取り違えたかを特定して、問題の解説に書く（→ `study-material`）。
6. **計画は聞く。中身は聞かずに進める。** 日程・量・時刻・作る教材の種類・買う物は、案を出して User に聞く。
   解説・図・採点・分析は聞かない。「任せる」と言われたら計画も決めて実行し、
   「まず計画だけ」と言われたら案を1つ出して止まる。

## どのスキルへ行くか

| ユーザーの言うこと | 使うスキル |
|---|---|
| 「◯◯の勉強を始めたい」「学習計画を立てて」 | **study-init** |
| 「進捗どう？」「今週どうだった」「レビューして」 | **study-review** |
| 「◯◯を教材にして」「解説を作って」「要点をまとめて」 | **study-material** |
| 「問題集を台帳にして」「採点して」「集計して」「◯回目を解いた」 | **drill-ledger**（採点 → 手書きを読む → 解説と類題は **study-material**） |
| 「ここが分からない」「追加で解説して」 | **study-material** ②（図1枚＋メモ。解説ファイルは書き換えない） |
| 「直前に見るものが欲しい」／本番の約1週間前 | **study-material** ④（最終確認ノート。Claude から提案する） |
| 「受けてきた」「合格した／落ちた」 | 同じ返事で3つ聞く（分からなかった問題の分野と中身・時間配分・手応え）→ `project-plan.md` §6 |
| 「問題出して」「テストして」「覚えられているか確認して」 | **recall-drill** |
| 「遅れてる」「間に合わない」「計画を引き直して」 | **study-replan** |
| 「終わったので振り返りたい」 | `{{TEMPLATE_REPO}}/template/retrospective/` の設計メモに従う |

## 毎セッション共通の作法

**開始時**
1. `STATUS.md` を読む（軽い。ここが状態復元の起点）
2. User が進捗を報告したら、**その場でガントに反映する**。終了時までためない。
   セッションが正式に閉じない日があり、ためるとガントが古いまま残る。
3. 一問一答の日替わりページを回している期間は `python ledger/daily.py pace` を流す。
   日付をまたいで解いた日が2日続いていたら、**量を減らす案を出す**（黙って減らさない。量は計画）。
4. User の指摘・要望・決定は、**その場で** `project-plan.md` §6 に言葉のまま1行足す（振り返りの軸になる）。

**終了時**（User が「終わり」と明示したときだけ。「コミットして」は終了の合図ではない）
1. `STATUS.md` を最新化
2. `project-plan.md` の進捗ログに1エントリ追記
3. ガント（`st` / `pct` / `COMMENTS` / `TODAY`）を更新 → PNG 再生成を確認
4. `THIS-WEEK.md` の済んだ行を、末尾の畳んだ枠へ移す（まだやっていない行が先頭に残る形を保つ）
5. **push されているか確認する**（ローカルコミットは作業中に頻繁でよいが、
   セッションを閉じる前に必ずリモートまで上げる）

## 長い処理を始める前に

大量の教材生成や問題の一括読み込みは、**着手前に分割単位を宣言する**。

> 「全◯件を △件ずつ、□回に分けます。各回の終わりで成果物を確定させるので、
>  途中で止まっても失われません。所要はおよそ ◯分です。」

E資格では、問題集の一括読み込みでセッションリミット際どい状態が3日続き、
作業が途中で切れるリスクを抱えたまま走った。**時間がかかるなら先に言う。**

## 命名の規則（これは守る）

User が目にする名前・指標名は、**すべて説明的な日本語**にする。
`FC` `N3` `D5` `gen_2nd.py` のような略号は Claude 内部だけで使い、会話に出さない。
新しい指標を導入するときは、**初出で必ず1文の定義を添える**。
1文で定義できない指標は導入しない。

（E資格では「FC・N・D が何の略か分からない」「gen_2nd.py が何のファイルか分からない」
「『安い絞り込み』が何を指すか分からない」が同時に起きていた。）

- タスクの番号や節の番号を User に書くときは、同じ行に中身を一言で添える（番号だけでは通じない）
- 問題は、教材と同じ呼び方で呼ぶ（台帳の通し番号を User に出さない）
- 後のタスクは「残り」と書かず、「いつ・急ぐか」を行の頭に書く（期日の無い「残り」は、今やることに見える）
